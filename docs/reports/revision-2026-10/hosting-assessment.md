# Free-hosting assessment — 2026-10-10

The proposed split is a Vercel Hobby static Vite site with a separate Render Free FastAPI service. This is a configuration choice for a personal, non-commercial academic demonstration, not a deployed or guaranteed free public service. Research pages use generated static JSON; Design Studio prediction and optimization require the API. The current `frontend/vercel.json` requires complete, validated research exports at build time and rewrites client routes. `render.yaml` starts a frozen environment and a prebuilt trusted model, without fitting at request time.

| Constraint | Official provider documentation checked on 2026-10-10 | Local implication |
|---|---|---|
| Render Free compute | [0.1 CPU and 512 MB RAM](https://render.com/docs/compute-plans); [idle spin-down after 15 minutes, roughly one-minute wake-up, ephemeral filesystem and 750 free instance-hours per workspace per calendar month](https://render.com/docs/free). | Keep research reading static and make Studio service-unavailable/cold-start behavior clear. Verify actual model-load RSS and response latency on the deployed instance. Do not promise always-on inference. |

| Public asset size | [Cloudflare Pages caps a single asset at 25 MiB](https://developers.cloudflare.com/pages/platform/limits/); Vercel's [documented static upload limit](https://vercel.com/docs/limits) applies to CLI source upload. | Keep the static site on the already configured Vercel candidate. The final local `frontend/dist` has 134 files totaling 15,347,819 bytes; its largest file is `research/signals.json` at 7,610,410 bytes. This is a local asset measurement, not a hosted quota or transfer test. |

The canonical source tree occupies about 428 MB of original data; `artifacts/results/signals_detail.json` alone is about 89 MB and is deliberately not staged by `frontend/scripts/stage-research.mjs`. A separate runtime installation with `uv sync --frozen --no-dev` and final backend source loaded the trusted `baseline_only` artifact and served `/v1/health` with `ready=true` and `/v1/meta` successfully; measured RSS was **215,688 KiB** after startup on this host. The final built preview served all eight deep links and representative analysis/bundle/signals JSON as HTTP 200. These local checks do not establish a Render or Vercel deployment, Render Free memory under cold start, actual CORS behavior, caching, transfer quota, or provider account eligibility. Hosting still needs a real provider build and live checks for `/`, all deep links, `/research/analysis/index.json`, representative analysis JSON and room imagery, `/v1/health` with JSON `ready=true`, `/v1/meta`, prediction, optimization, exact CORS origin, model memory, and cold-start/offline presentation. No provider account, custom domain, payment method, external deployment or purchase was used for this assessment.

The 360-minute CI job uses the standard `ubuntu-latest` runner. [GitHub documents standard hosted runners as free and unlimited for public repositories](https://docs.github.com/en/actions/reference/runners/github-hosted-runners); that does not establish that this specific account's future workflow is enabled or passing. CI runs on main pushes and pull requests, canceling superseded runs on the same ref. No larger paid runner or paid hosting plan is configured or authorized.
